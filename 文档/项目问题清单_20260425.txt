## 一、高风险问题（4个）- 必须修复

### 问题 1: access_token Cookie HttpOnly 设置为 false - XSS 漏洞 🔴

**严重程度**: 高
**影响**: 攻击者可通过 XSS 攻击窃取用户 Token

**文件位置**: `src/app/api/v1/auth/login/route.ts` 第 138-151 行

**问题代码**:
```typescript
response.cookies.set('access_token', accessToken, {
  httpOnly: false, // 前端需要读取
  secure: isProd,
  sameSite: 'lax',
  path: '/',
  maxAge: 60 * 15, // 15 分钟
});
```

**说明**: 将 `httpOnly` 设置为 `false` 允许 JavaScript 读取 Token，如果网站存在 XSS 漏洞，攻击者可以直接窃取用户会话 Token。

**建议修复**:
1. 将 `httpOnly` 改为 `true`
2. 前端通过 HttpOnly Cookie 自动发送（浏览器会自动处理）
3. 如前端确实需要读取 Token，应仅用于显示（如用户名），而认证相关操作应通过 Cookie 自动发送

### 问题 2: MFA 恢复码使用 Math.random() - 密码学不安全 🔴

**严重程度**: 高
**影响**: 恢复码可被预测，攻击者可绕过双因素认证

**文件位置**: `src/app/api/v1/users/mfa/route.ts` 第 14-22 行

**问题代码**:
```typescript
function generateRecoveryCodes(): string[] {
  const codes: string[] = [];
  for (let i = 0; i < 10; i++) {
    const part1 = Math.random().toString(36).substring(2, 6).toUpperCase();
    const part2 = Math.random().toString(36).substring(2, 6).toUpperCase();
    codes.push(`${part1}-${part2}`);
  }
  return codes;
}
```

**说明**: `Math.random()` 不是密码学安全的随机数生成器，其输出可被预测。

**建议修复**:
```typescript
import crypto from 'crypto';

function generateRecoveryCodes(): string[] {
  const codes: string[] = [];
  for (let i = 0; i < 10; i++) {
    const part1 = crypto.randomBytes(2).toString('hex').toUpperCase();
    const part2 = crypto.randomBytes(2).toString('hex').toUpperCase();
    codes.push(`${part1}-${part2}`);
  }
  return codes;
}
```

### 问题 3: Docker 生产配置使用默认 JWT 密钥 🔴

**严重程度**: 高
**影响**: 使用可预测的默认密钥，攻击者可伪造 Token

**文件位置**: `docker-compose.prod.yml` 第 12-13 行

**问题代码**:
```yaml
- JWT_SECRET=${JWT_SECRET:-github-platform-secret-key-2024}
- JWT_REFRESH_SECRET=${JWT_REFRESH_SECRET:-github-platform-refresh-secret-2024}
```

**说明**: 生产环境使用硬编码的默认密钥，如果部署时未设置环境变量，密钥即为明文。

**建议修复**:
1. 移除默认值，强制要求设置环境变量
2. 或使用更复杂的随机默认值（但仍需部署时更新）
3. 添加启动检查，未设置密钥时拒绝启动

### 问题 4: MFA 密钥在验证前保存到数据库 🔴

**严重程度**: 高
**影响**: 用户可能无法完成验证流程，导致 MFA 处于错误状态

**文件位置**: `src/app/api/v1/users/mfa/route.ts` 第 96-99 行

**问题代码**:
```typescript
// 保存 MFA 密钥到数据库
await prisma.user.update({
  where: { id: userId },
  data: {
    mfaSecret: base32.stringify(secret),
    mfaEnabled: false, // 等待验证
  },
});
```

**说明**: TOTP 密钥在用户完成验证流程之前就保存到数据库，如果用户中途放弃或验证失败，数据库中存在无效的密钥。

**建议修复**:
1. 验证成功后再保存 MFA 密钥
2. 或使用临时字段存储未验证的密钥，验证成功后移动到正式字段

第一部分：项目概述

## 1.1 项目目标

将项目打造为 **生产级别的仓库式知识托管与交流平台**，类似 GitHub 的核心功能，
同时具备独特的用户体验和完整的运营管理能力。

## 1.2 核心技术栈

- 前端：Next.js 14 + TypeScript + React
- 后端：Next.js API Routes
- 数据库：PostgreSQL + Prisma ORM
- 缓存：Redis
- 文件存储：MinIO (S3 兼容)
- 部署：Docker + Docker Compose

## 1.3 项目现状

| 模块 | 完成度 | 说明 |
|------|--------|------|
| 基础框架 | 90% | Next.js 14 + 组件库 |
| 用户系统 | 85% | 登录/注册/个人资料 |
| 仓库系统 | 30% | 基础 CRUD，需重构 |
| 讨论区 | 70% | 完整功能 |
| 管理面板 | 60% | 基础功能，需扩展 |
| 通知系统 | 50% | SSE 已实现，需规范 |

**虚拟磁盘架构**：仓库 = 用户的私有空间，类似 Windows 磁盘

## 2.2 数据库扩展

### 2.2.1 新增表：RepoFile（仓库文件）

```prisma
model RepoFile {
  id          String   @id @default(cuid())
  repoId      String
  parentId    String?  // null 表示根目录
  name        String
  type        String   // 'file' | 'folder'
  size        Int      @default(0)
  mimeType    String?
  content     String?  // 小文件内容
  storageKey  String?  // MinIO 存储路径
  hash        String?  // 文件 hash，用于去重
  depth       Int      @default(0)  // 目录深度
  path        String   // 完整路径，如 /src/components/Button.tsx
  sortOrder   Int      @default(0)
  isDeleted   Boolean  @default(false)
  deletedAt   DateTime?
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  repo        Repository @relation(fields: [repoId], references: [id])
  parent      RepoFile?  @relation("FileParent", fields: [parentId], references: [id])
  children    RepoFile[] @relation("FileParent")

  @@index([repoId, parentId])
  @@index([repoId, path])
}
```

## 2.4 文件操作流程

### 2.4.1 创建文件夹

```
1. 用户点击"新建文件夹"或右键菜单
   ↓
2. 输入文件夹名称
   ↓
3. POST /api/repos/[username]/[repoName]/files
   {
     "name": "src",
     "type": "folder",
     "parentId": null
   }
   ↓
4. 返回新文件夹信息
   ↓
5. 更新文件树 UI
```

### 2.4.2 移动/重命名文件

```
1. 用户拖拽文件到新位置 或 右键"重命名"
   ↓
2. PATCH /api/repos/[username]/[repoName]/files/[id]
   {
     "parentId": "new-parent-id",
     "name": "new-name.tsx"
   }
   ↓
3. 更新文件路径（自动更新所有子文件的 path）
   ↓
4. 返回更新后的文件信息
```

### 2.4.3 删除文件（回收站）

```
1. 用户右键"删除"或按 Delete
   ↓
2. 确认对话框
   ↓
3. PATCH /api/repos/[username]/[repoName]/files/[id]
   { "isDeleted": true, "deletedAt": now }
   ↓
4. 如果是文件夹，递归标记所有子文件
   ↓
5. 30 天后自动永久删除（Cron Job）
```

## 2.5 Fork 申请流程

```
1. 用户点击 "Fork"
   ↓
2. 检查用户状态
   - 如果被禁言 (mute): 返回 403 "您已被禁言，无法发送 Fork 申请"
   - 如果被仓库限制 (repo_limit): 返回 403 "您已被限制创建仓库"
   ↓
3. 检查仓库 visibility
   - private: 禁止 Fork
   - public: 直接 Fork
   - request: 进入申请流程
   ↓
4. 申请页面
   用户填写申请留言
   ↓
5. 提交申请
   POST /api/repos/[username]/[repoName]/fork-request
   { "message": "想学习这个项目..." }
   ↓
6. 仓库所有者收到通知
   在仓库设置中看到申请列表
   ↓
7. 审批
   PATCH /api/fork-requests/[id]
   { "action": "approve" | "reject", "note": "备注" }
   ↓
8. 结果通知
   - 通过：用户获得仓库副本
   - 拒绝：通知用户并说明原因
```

### 2.5.1 Fork 申请超时管理

**说明**：正常的 Fork 申请由仓库主人自己处理，管理面板不介入

| 场景 | 处理方式 |
|------|---------|
| 正常 Fork 申请 | 仓库主人自己处理，管理面板不介入 |
| 超时丢弃 | 申请超过 **7 天**未处理，自动标记为过期 |

```typescript
// Cron Job 自动清理
async function cleanupExpiredForkRequests() {
  const expiredDate = new Date(Date.now() - 7 * 24 * 60 * 60 * 1000);
  
  await prisma.forkRequest.updateMany({
    where: {
      status: 'pending',
      createdAt: { lt: expiredDate }
    },
    data: { status: 'expired' }
  });
}
```

## 2.6 分片上传设计

### 2.6.1 上传流程

```
1. 前端计算文件 hash
   ↓
2. 检查是否已存在（秒传）
   - 存在：直接返回成功
   - 不存在：继续上传
   ↓
3. 分片上传
   - 每片 5MB
   - 并发上传 3 个片
   - 支持断点续传
   ↓
4. 服务端合并分片
   ↓
5. 验证 hash
   ↓
6. 创建文件记录
```

### 2.6.2 文件夹上传

```
1. 前端选择文件夹
   ↓
2. 递归读取文件夹结构
   ↓
3. 创建所有文件夹
   ↓
4. 并发上传文件
   ↓
5. 批量创建文件记录
```

## 3.2 API 集成限制检查

| API 文件 | 检查类型 | 被限制时的行为 |
|---------|---------|--------------|
| discussions/route.ts POST | 禁言检查 | 返回 403：创建讨论被禁止 |
| repos/[username]/[repoName]/fork-request/route.ts POST | 禁言检查 | 返回 403：Fork 申请被禁止 |
| repos/route.ts POST | 仓库限制 | 返回 403：创建仓库被禁止 |
| repos/[username]/[repoName]/fork/route.ts POST | 仓库限制 | 返回 403：Fork 仓库被禁止 |
| repos/[username]/[repoName]/upload/route.ts POST | 存储限制 | 返回 403：上传文件被禁止 |

## 3.3 限制类型详解

| 类型 | 标识 | 限制内容 | 适用场景 |
|------|------|---------|---------|
| 禁言 | mute | 禁止 Fork 申请、禁止发布讨论 | 发布违规内容、恶意攻击 |
| 仓库限制 | repo_limit | 禁止创建仓库、禁止 Fork | 传播违规内容、恶意 Fork |
| 存储限制 | storage_limit | 限制上传文件和仓库大小 | 滥用存储资源 |

### 禁言详细说明

| 行为 | 禁言后状态 |
|------|-----------|
| ❌ 发送 Fork 申请 | 禁止申请 Fork 他人仓库 |
| ❌ 发送讨论 | 禁止发布新讨论 |
| ✅ 发表评论 | 允许 |
| ✅ 浏览公开内容 | 允许 |
| ✅ Star/Watch | 允许 |
| ✅ 操作自己的仓库 | 允许 |

### 仓库限制详细说明

| 行为 | 限制后状态 |
|------|-----------|
| ❌ 创建仓库 | 禁止 |
| ❌ Fork 仓库 | 禁止 |
| ✅ 访问公开仓库 | 允许 |
| ✅ 评论/讨论 | 允许 |
| ✅ 上传文件到自己仓库 | 禁止 |

### 存储限制详细说明

| 行为 | 限制后状态 |
|------|-----------|
| ❌ 上传大文件 | 禁止（单文件限制） |
| ❌ 创建过多文件 | 禁止（总大小限制） |
| ✅ 浏览和下载 | 允许 |

**实现**：
```typescript
// components/ui/BackButton.tsx
interface BackButtonProps {
  fallback?: string;  // 默认返回地址
  preserveHistory?: boolean;  // 是否使用浏览器历史
}

function BackButton({ fallback = '/', preserveHistory = false }: BackButtonProps) {
  const router = useRouter();

  const handleBack = () => {
    if (preserveHistory && window.history.length > 1) {
      router.back();
    } else {
      router.push(fallback);
    }
  };

  return (
    <button onClick={handleBack} className="back-button">
      ← 返回
    </button>
  );
}
```
